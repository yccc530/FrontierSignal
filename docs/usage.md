# 使用指南

[返回项目首页](../README.zh-CN.md) · [安装与启动](installation.md) · [配置说明](configuration.md)

## 第一次使用

1. 打开 `http://localhost:8000`，确认侧栏显示「本地服务已连接」。
2. 进入「信息来源」，启用需要的来源，点击「采集全部」，或点击某个来源右侧的采集按钮。
3. 进入「运行任务」，等待已提交的任务结束。查看新增、更新、重复、过滤和失败数量。
4. 打开「资讯库」，查看实际内容。点击标题打开详情，点击原文链接访问发布页面。
5. 需要中文解读时，按 [配置说明](configuration.md) 接入 LLM 并验证；然后点击资讯库的「分析待处理」。

默认调度已开启，启用的自动来源也会按设定间隔采集。手动提交只代表任务进入后台队列，最终结果以「运行任务」为准。采集和分析期间，页面仍可浏览。

首次打开没有历史记录是正常情况。来源按预算轮换查询，不会在一轮内扫描全部主题；增长榜还需要时间窗口和实际快照。

## 七个页面各做什么

| 页面     | 主要操作                                                                       |
| -------- | ------------------------------------------------------------------------------ |
| 技术推荐 | 浏览增长项目、模型、工具、工作流、热点、论文及官方发布；调整研究偏好和推荐份额 |
| 开源项目 | 切换增长异动、新项目和全部项目；查看 Stars、增长依据、历史和版本信息           |
| 资讯库   | 搜索、筛选、排序、分页；阅读详情、原文、中文解读与处理记录                     |
| 我的收藏 | 查看已收藏的资讯，继续筛选和取消收藏                                           |
| 信息来源 | 添加来源，管理启用状态、自动采集、频率和专项范围；查看覆盖情况                 |
| 运行任务 | 查看最近 100 次采集、分析和接口验证；定位错误并重试采集                        |
| 系统设置 | 配置模型非敏感参数、验证接口、管理分类并查看运行与用量信息                     |

## 调整采集与推荐

这三个设置影响不同环节：

| 设置     | 在哪里修改                       | 作用                                             |
| -------- | -------------------------------- | ------------------------------------------------ |
| 采集范围 | 「信息来源」中支持专项查询的来源 | 决定后续主动查询哪些方向，不删除已入库的其他内容 |
| 研究偏好 | 「技术推荐」的研究偏好区域       | 调整推荐对关注方向的匹配，不修改采集任务         |
| 推荐份额 | 「技术推荐」的「推荐份额」       | 设置栏目条数、方向权重和重复推荐观察时间         |

例如关注视频和 3D 模型：在 Hugging Face 模型来源的采集范围中选择相关方向；在研究偏好中选择视频、3D；再提高它们的推荐份额。GitHub 来源的范围需要单独设置。

栏目条数可以设为 `0–12`，`0` 隐藏该栏目；方向份额为 `1–5`，是相对权重，不是固定结果数量。没有符合条件的候选时不会凑数。重复观察窗口为 `1–168` 小时，默认 24 小时。

实际进入视口的推荐会记录展示状态；近期未发生实质更新的内容降低优先级。Stars 或下载数刷新不算内容更新，有真实增长异动的项目不会仅因展示过而被隐藏。

## 读懂开源项目榜单

「增长异动」优先显示短期增长显著的项目；「新项目」按真实仓库创建时间观察新仓库；「全部项目」保留已发现项目，便于检索和回看。

| 指标                           | 含义                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| 累计 Stars                     | 最近一次观测时的总数，只表示规模                                     |
| 本地约 1h / 6h / 24h / 7d 净增 | 对应时间窗口内两次真实快照的差值，包含取消 Star 的影响               |
| 今日 / 昨日获星（UTC）         | GitHub 返回的逐日获星记录，按 UTC 日统计，和本地滚动窗口不是同一口径 |
| 窗口平均 / 小时                | 根据实际统计时长计算的增长速度                                       |
| 加速倍数                       | 短期速度与此前基线的比较；缺少基线时为空                             |
| 待积累 / 未知                  | 暂无足够、有效或足够新的观测，不等于零增长                           |

可以展开增长依据或查看历史，核对统计起止时间。让应用持续运行可以逐步形成基线，但每个仓库按预算轮流跟踪；运行满 7 天不保证所有仓库都有有效 7 天窗口。

增长榜为空时，先看新项目和全部项目，再检查 GitHub 采集任务是否成功。不要把没有异动理解为系统一定出错，也不要通过反复触发采集来解决 API 限额。

## 检索、阅读和收藏

- **关键词**：同时搜索原始标题、正文以及已有中文解读。
- **内容类型**：可选择模型、工具与应用、项目案例、创作工作流、研究论文或数据集。
- **更多筛选**：包含日期、已读状态、分析状态和技术筛选；选择「全部原始资讯」可查看未进入技术推荐的记录。
- **排序**：可按最新发布 / 收录、重要性或技术相关性排列。缺少发布时间的记录会区分首次收录时间。
- **阅读**：从资讯列表打开详情会标为已读，也可以手动切换为未读。
- **收藏**：点击收藏图标，状态保存到数据库，刷新和重启后保留。

详情保留原始标题、可获取的正文、来源链接、中文解读、相关记录与处理日志。RSS 可能只提供摘要或标题，工作台不会把它伪装成全文；完整文章请打开原始链接。

## 阅读模型与科研证据

查看 GLM 或 Meta：在「资讯库」选择内容类型「模型资讯」，发布团队选择「智谱 / Z.ai」或「Meta」。
Meta 汇总 Llama 与 facebook 官方账号，原始模型 ID、链接和账号核验依据仍分别保留；中文摘要在实际分析完成后显示。

模型详情区分官方发布日期、Hub 创建 / 更新时间、首次采集和指标观测时间。提交 SHA 代表仓库修订，不自动当成产品版本。

模型卡中的分辨率、时长、显存、输入输出、硬件及授权信息以原文引用呈现；它们是发布者说明，不是 FrontierSignal 的实测结论。缺少许可、版本或可用性声明时保持未知。

工具、工作流和科研内容同样保留依赖、宿主、授权、实验和复现线索。Vibe 项目需要已读取的 README 中有作者明确声明，不仅凭标签判断。论文、模型、数据集和代码之间按明确引用建立关联，原始记录分别保留。

## 管理来源

「启用」决定该来源能否被采集；「自动」决定是否按频率运行。关闭自动但保持启用，可以手动采集。关闭启用不删除历史资讯。修改频率后离开输入框即提交保存，支持 15 分钟至 7 天。

新增固定项目的版本跟踪：

1. 点击「添加来源」。
2. 来源类型选择「GitHub 项目版本发布」。
3. 输入名称、`owner/repository` 和采集间隔，保存。

新增公开 RSS/Atom：

1. 确认地址是实际订阅地址，使用 HTTPS。
2. 若主机不在允许列表，先在 `.env` 的 `FS_EXTRA_FEED_HOSTS` 中加入域名并重启；详见 [配置说明](configuration.md)。
3. 在「添加来源」选择「公开订阅（RSS / Atom）」，填写地址并保存。
4. 手动采集一次，在「运行任务」查看实际结果。

GitHub 项目发现、HF 模型和数据集等默认来源已经存在，无需重复添加。来源页中的扫描覆盖显示各方向最后扫描、候选、新增、更新、重复和错误；单个查询零结果不代表整个方向没有内容，未扫描也不代表已覆盖。

GLM / Meta 复用 Hugging Face 模型来源，可在该来源的「采集方向与扫描记录」查看优先跟踪账号。
「采集覆盖与持续观察」集中显示重点账号最近成功时间和采集错误。

## 处理失败任务

| 状态          | 含义与操作                                           |
| ------------- | ---------------------------------------------------- |
| 排队 / 运行中 | 等待后台任务结束，不必重复提交                       |
| 成功          | 本次任务完成，新增为 0 也可能是没有新内容            |
| 部分失败      | 已获取的数据已保存，部分请求或核验失败；查看具体错误 |
| 失败          | 根据错误检查网络、接口、权限或配置，然后重试         |
| 中断          | 上次运行未正常结束，恢复服务后再处理                 |

采集失败可从运行任务中重试，也可以到来源页重新采集。中文分析失败则在资讯详情中重试；已成功且内容未变的记录不会因每次启动或换模型而自动重跑。

HTTP 429 通常需要等待或降低频率；401/403 应先检查权限或配置。更具体的处理见 [故障排查](troubleshooting.md)。

## 长期使用

保持后端和数据库运行，定期查看失败任务并执行 [备份](backup-recovery.md)。运行覆盖监控根据实际采样计算，休眠或停机形成的缺口不会补造；24 小时覆盖也不代表全部来源零故障。

任务结果、样本覆盖和模型用量都以你自己的本地运行情况为准。历史验收文档中的新闻数量、任务 ID 和截图数据不随仓库分发。

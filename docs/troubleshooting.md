# 故障排查

[返回项目首页](../README.md) · [安装指南](installation.md) · [配置说明](configuration.md)

## 先定位哪一层出错

| 现象                            | 优先检查                                      |
| ------------------------------- | --------------------------------------------- |
| 浏览器连接被拒绝                | 后端是否启动、8000 端口是否正确、WSL 是否运行 |
| 健康接口可访问，首页 404 或空白 | 是否完成前端构建，并在构建后重新启动后端      |
| 后端提示数据库不可用            | PostgreSQL 状态、连接地址、密码、迁移         |
| 工作台正常但没有资讯            | 任务是否完成，来源是否启用，筛选是否过窄      |
| 有资讯但没有中文解读            | LLM 三项配置、接口验证、分析状态              |
| 增长榜为空或显示待积累          | 真实快照、时间窗口、近期增长门槛              |
| 手动采集可用，自动不运行        | 调度开关、来源自动开关、运行时间和调度锁      |

## 页面打不开或空白

先确认应用在项目根目录成功启动。日常入口是 `http://localhost:8000`，5173 只在运行 Vite 开发服务器时可用。

检查健康接口，选择对应终端：

```powershell
Invoke-RestMethod http://localhost:8000/api/health
```

```bash
curl --fail --noproxy '*' http://127.0.0.1:8000/api/health
```

如果接口正常但页面打不开，先停止后端，执行 `npm --prefix frontend run build`，再启动。后端只在启动时挂载已经存在的 `frontend/dist`。更新界面代码后也需要重新构建。

WSL 用户先在 WSL 内验证 `127.0.0.1:8000`，再从 Windows 浏览器验证 `localhost:8000`。只在 Windows 失败时检查 WSL 的 localhost 转发和本机代理；不要把开放公网监听当成替代办法。

8000 已被占用时，先确认是否是自己启动的后台服务；可用 `uv run python scripts/background.py --stop` 停止该启动器管理的服务。它仅适用于 WSL/Linux，不会替换无关进程。不要启动多个 worker。

## 数据库无法连接

Docker 路径依次检查：

```text
docker info
docker compose ps db
docker compose logs --tail 50 db
uv run python scripts/wait_db.py
```

Docker 未启动时先启动 Docker Desktop；WSL 中还需启用当前发行版的集成。数据库尚未启动时运行 `docker compose up -d db`。默认主机端口是 **54329**，不是 5432。

用户态数据库路径使用 `uv run python scripts/local_postgres.py` 启动，日志在 `.runtime/postgres.log`，与 Docker 是两种替代部署方式。

密码错误时核对 `FS_DATABASE_URL` 与实际数据库角色。修改 `.env` 的 `POSTGRES_PASSWORD` 不会更新旧卷中的密码。不要删除数据卷或覆盖 `.env` 来试错。

数据库可连接但缺少表或迁移时，停止后端并运行 `uv run alembic upgrade head`。若提示缺少 `vector` 扩展，检查是否使用了支持 pgvector 的实例。数据库重启可能导致调度锁失效，数据库恢复后也需重启后端。

## 没有内容或没有自动采集

1. 在「信息来源」确认来源启用；需要自动运行时，同时开启「自动」。
2. 在「运行任务」检查状态；任务提交成功不等于采集已完成。
3. 在资讯库清除关键词、日期和主题筛选；更多筛选中选择「全部原始资讯」。
4. 查看 `FS_SCHEDULER_ENABLED`，进程环境变量可能覆盖 `.env`；修改后重启。
5. 确认后端和 WSL 持续运行。后台启动器不提供开机自启，休眠期间不会采集。

RSS 返回 304 代表内容未变化，新增为 0 是正常结果。专题采集按查询组轮换，本轮没扫到某方向也不代表异常。长时间停机可能错过 RSS 当前窗口之外的历史内容。

## 外部来源报错

| 错误                            | 处理方向                                                            |
| ------------------------------- | ------------------------------------------------------------------- |
| 401 / 403                       | 检查访问权限、令牌和错误说明；部分 403 也可能是限额，不尝试登录绕过 |
| 429 / rate limit                | 等待限额恢复，降低频率或预算；GitHub 可选配置自己的 Token           |
| timeout / connection failed     | 核对网络和代理是否从后端环境可达，查看请求超时设置                  |
| `non-public address`            | DNS 返回非公网目标，检查 DNS / 代理配置，不关闭访问校验             |
| `explicitly allowed feed host`  | 订阅主机未允许，按配置文档补充 `FS_EXTRA_FEED_HOSTS` 并重启         |
| `incomplete_results` / 部分失败 | 已获取内容会保留，检查具体失败组，不当作全量成功                    |

采集器和 LLM 使用的代理配置不同，参见 [网络代理与订阅域名](configuration.md#网络代理与订阅域名)。内容只有标题或摘要时，打开原文阅读；系统不会自动抓取任意外链补全文。

## 增长值与预期不一致

累计 Stars、本地净增和官方 UTC 日获星是不同口径。查看增长依据中的统计窗口；本地快照不足、基线过期或旧基线为零时，相关数值可能为空。

默认增长榜不展示所有热门仓库。没有达到异动门槛的项目可以在「新项目」或「全部项目」查看。每轮查询与跟踪都有预算，不保证全部仓库每小时都有快照；反复手动采集也不能补出过去 7 天的历史。详细口径见 [使用指南](usage.md#读懂开源项目榜单)。

## 模型分析失败

确认 `.env` 中地址、Key、模型 ID 均已配置，地址不包含 `/chat/completions`。重新加载密钥需要重启；页面修改非敏感参数则保存后生效。

在设置页验证接口，或执行 `uv run python scripts/probe_llm.py`。该命令有实际用量；已有分析任务或配置不完整时通常退出 2，探测任务失败退出 1，通过结构校验才退出 0。

| 现象               | 建议                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| 401 / 403          | 确认密钥有效、网关有权限、请求模型 ID 正确                             |
| 404                | 核对基础路径和模型名称，显示名称不一定是请求 ID                        |
| 超时               | 检查网络；在服务实际需要时提高超时，上限 180 秒                        |
| JSON mode 不支持   | 保持 `FS_LLM_JSON_MODE=false`                                          |
| 格式或中文校验失败 | 服务响应未满足结构、中文、分类或评分要求，保留原文后重试或更换兼容模型 |
| 保存设置返回 409   | 分析任务尚未结束，或参数由进程环境变量管理                             |

自动失败重试有次数限制，认证 / 配置类错误不会无限重试。修复后在资讯详情中单独重试；已成功且内容未变的记录不会因换模型自动全部重跑。Token 统计只包括服务返回的 usage，不是完整账单。

## 提交问题

使用 [GitHub Issues](https://github.com/yccc530/FrontierSignal/issues)，提供：

- 操作系统、WSL 发行版、Python / Node 版本和启动方式。
- 当前提交号：`git rev-parse --short HEAD`。
- 复现步骤、期望行为与实际行为。
- 运行任务的具体错误；后台启动器日志为 `.runtime/backend.log`，前台模式看终端输出。

提交前删除密钥、认证请求头、数据库连接密码及其他私密内容，不上传 `.env` 或完整备份。历史环境验证范围见 [验收记录](validation-history.md)，不能作为任意机器已通过部署的证明。

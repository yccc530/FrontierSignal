# 技术情报推荐与观测窗口

日期：2026-10-22。状态：已实现，真实运行与测试记录见 testing.md。

## 边界

延续现有模块化单体、数据库和 UI。采集器只产生结构化记录；存储处理去重、原始快照及项目观察；
推荐读取数据库，不在 Web 请求中采集或调用模型。X / Reddit 当前不接入，统一 Collector 接口仍可扩展。

项目热榜使用 GitHub 官方 REST 搜索及仓库接口；不声称复刻 GitHub 官网 Trending 名次，
不采用非官方 Trending 镜像、登录态或网页绕过。API 候选覆盖有界，不承诺全站无遗漏。
官方接口实际验证：`https://api.github.com/search/repositories`；具体查询保存在项目原始记录。

## 发现与质量

初版仅限制最近 push，技术分、累计 Stars 与首次收录时间共同排序，导致老牌仓库长期占榜。
当前改为增长异动发现：8 组技术主题与以下 4 个候选范围交叉轮换，查询页在 1..3 间轮换。

| 范围 | Stars 区间 | 排序与活跃条件 |
| --- | --- | --- |
| 近 7 天创建 | 至少 5，无上限 | Stars 降序，仅比较同龄新项目；近 14 天 push |
| 8..30 天创建 | 至少 5，无上限 | 更新排序；近 14 天 push |
| 31..90 天创建 | 20..20000 | 更新排序；近 14 天 push |
| 中小项目新动向 | 20..50000 | 更新排序；近 3 天 push，不限制年龄 |

所有范围排除 fork 和归档仓库；查询使用 UTC 日期。累计 Stars 只用于候选范围及同龄新项目初筛，
不进入最终动量分。旧版本游标自动切换为 strategy=2，不删除已有项目。
近 30 天项目不设 Stars 上限，避免遗漏刚发布就迅速超过数千 Stars 的项目。
每小时默认 2 组查询、每组 10 个候选；跟踪 10 个项目并读取最近 3 个发布。
跟踪约 70% 名额优先给近 90 天项目及近期获星活跃者，其余保留给最久未尝试的其他仓库。
官方获星历史每轮最多 8 个，分配给新候选与跟踪项目；根目录代码核验最多 3 个。
所有覆盖均有界，可能遗漏低于门槛、未匹配主题或不在当前页的项目。

根目录存在代码文件才标记 has_code=true；仅有语言、src 目录或非空仓库不会冒充完整代码核验。
根目录没有代码时 has_code 保持未知，因为代码可能在子目录。许可证、发布时间、实际代码线索
是可解释质量因素，不等于独立验证项目可运行或技术创新主张。清单/面试/营销内容降权。

GitHub 稳定仓库 ID 对应一个项目资讯。Stars、Forks 等指标变化只更新观测，不修改内容哈希，
不重复生成新闻、不重复调用 LLM。代码介绍真正变化时仍正常重新分析。版本按 release ID 去重。
各跟踪组内按最久未尝试者优先；失败也记录尝试时间，以避免卡在首批失败项目。

## 官方获星历史

`/repos/{owner}/{repo}/stargazers/history` 已在真实公共 API 验证返回 weekly/days 记录。
校验每周 7 个非负计数及周总和，转换为明确 UTC 日期，保存最近 15 天及实际获取时间。
原始 weekly 数据保留在原始版本中，结构化日记录保存在 `repositories.star_history`。
缺失日期保持未知，不补零；不会据此伪造历史累计 Stars 快照。

当 UTC 本日已过 3 小时，使用本日截至观测时的获星数与实际窗口时长；更早时使用昨日完整 UTC 日。
UI 标注「今日/昨日获星 (UTC)」，与「快照净增」分开。对比此前 6 个完整 UTC 日的平均速度，
缺少任一基线日或此前速度为零时，加速倍数为未知，不填无限大。
历史接口失败保留原始项目与本地快照，任务标记部分失败；接口成功不代表搜索覆盖完整。

## Stars 时间窗口

每仓库每小时一个快照，小时内重复采集更新该小时的最后实际观测，观测时间不伪装成整点。
显示的是 Stars 净变化，可能为负，不等于新增 Star 用户数。

- 最新快照超过 6 小时：增长未知，等待刷新。
- 1h / 6h：对应基线允许最多再早 1 / 2 小时；按实际跨度计算每小时净增，不外推一天。
- 24h：使用相对最新快照 24 小时之前最近的一条真实基线，允许最多再早 6 小时。
- 7d：使用相对最新快照 7 天之前最近的真实基线，允许最多再早 12 小时。
- 不足、过期、未来数据或窗口不匹配：返回 null，不补 0、不插值、不虚构历史。
- API 同时返回 baseline_at、observed_at、window_hours；UI 显示「约24h / 约7d」和实际时间。

本地 24h / 7d 净增仍需等待一天/一周；官方日记录可提供首次发现时的独立证据。机器休眠、
限流、项目库过大或停机可能使窗口没有基线，此时仍显示未知。

## 技术与推荐

技术规则独立存储，覆盖中文/英文技术主题和实现、训练、推理、评测等线索；
普通商业、营销和娱乐内容降权。紧凑的 HN 技术标题允许基于明确工程词保留，
但“高分”“官方”“项目自述”均不等同于事实经过独立验证。

GitHub 优先采用有效的 1h、6h、24h 本地快照窗口；缺少本地窗口时采用官方日获星。
最新短窗口已经显示减速时，不回退到更早的热门数据。所有证据最多允许 6 小时观测延迟。
增长异动要求窗口实际增长至少 max(5, 窗口小时数)，平均至少 1 Star/小时，且相对规模增加
至少 8%，或速度达到此前平均的 2 倍。相对规模评分分母最小为 50，避免极小基数噪声。
快照的相对值是实际基期增幅；官方获星的相对值是占当前 Stars 的比例，两者分别标注。

动量分：速度最多 30 分、相对规模增长最多 25 分、加速最多 20 分、真实仓库年龄最多 10 分、
技术/代码/许可证最多 10 分、偏好最多 5 分；已读减 5 分。累计 Stars、push 和首次收录不加分。
首页「短期增长异动」只展示达到上述门槛的项目；「新项目观察」展示真实创建不超过 30 天的候选。
没有符合条件的增长时展示空状态，不用老牌项目补榜。全部历史项目仍保留在项目库。
API `pool=rising|new|all`，默认 rising；显式选择累计 Stars 排序时也只在所选范围内排序。

HN 热度只使用其 points / 评论与时间衰减；热点窗口 72h，保留 12h 新帖席位。
论文窗口 14 天，官方发布 30 天。高价值发现不计平台互动热度，避免把 Stars 与 points
直接混合。HF 使用实际资源更新时间参与时效判断，创建时间独立保留。
同一事件的原始记录不删除，首页通过精确 URL 与高置信关联压缩重复展示。

候选查询最多 1000 条，超过时 API 明示截断。未实现全历史事件聚类或大规模语义质量评测；
规则可能误判，原始内容可在资讯库查看，偏好可通过界面持久化调整。
